# Origin service

Сервис **хранения оригиналов**: принимает загрузку файла, складывает объект в **MinIO** и отдаёт тот же файл по `GET /files/{file_id}`. Он выставляет заголовки кэширования и поддерживает условный запрос `If-None-Match` с ответом **304 Not Modified**, чтобы кэш у EdgeCache мог ревалидировать объект без полной перекачки.

Проверка JWT для защищённых ручек делается через **Users service**: Origin по настройке `auth_verify_url` вызывает **`POST /auth/verify`** с телом `{"token":"<jwt>"}`. Если в ответе `active: true`, владельцем операции считается поле `user_id`. Публичная отдача файла по `GET /files/{file_id}` без заголовка авторизации рассчитана на то, что к ней ходит EdgeCache или другой кэширующий прокси.

Полная машиночитаемая спецификация: **`GET /docs/openapi.json`**. Интерактивно: **`GET /docs/`** (Swagger UI).

Параметры процесса и URL проверки токена задаются в **`config.yml`**.

## API

### `POST /files`

Создаёт запись о файле и сохраняет тело в хранилище. Нужен валидный JWT.

**Заголовки.** `Authorization: Bearer <access_token>`.

**Тело.** `multipart/form-data`, обязательное поле **`file`** с бинарным содержимым.

**Проверка доступа.** Origin извлекает токен из заголовка, вызывает Users **`POST /auth/verify`** и при успехе использует **`user_id`** из JSON ответа как владельца файла.

**Успех: 201.** JSON: `file_id`, `owner_user_id`, `filename`, `content_type`, `size_bytes`, `created_at` в формате RFC3339, **`download_url`**. Сейчас **`download_url` = `{download_base_url}/files/{file_id}`** из `config.yml`. Путь **`/download/{file_id}`** относится к EdgeCache в общей схеме; этот сервис сам такой URL не строит.

**Ошибки.** Тело ответа — JSON с полем **`error`**.

- **400** — нет части `file` или она не читается как файл в форме.
- **401** — нет префикса `Bearer`, токен не принят Users или `active` не true, сеть к auth недоступна, не‑200 от verify и т.п.: клиенту везде сообщение вида «token invalid».
- **413** — размер тела превышает `max_upload_size_bytes`.

**Не по контракту вики, но возможно.** **405** и **500** при сбоях хранилища или внутренних ошибках.

### `GET /users/me/files`

Список файлов **текущего** пользователя. Нужен JWT.

**Заголовки.** `Authorization: Bearer <access_token>`.

**Проверка доступа.** Тот же сценарий, что у `POST /files`: verify у Users, список строится по **`user_id`**.

**Успех: 200.** JSON: **`items`** — массив объектов с полями `file_id`, `filename`, `content_type`, `size_bytes`, `created_at`, `download_url`; **`total`** — число элементов в `items`.

**Ошибки.**

- **401** — как у загрузки.

**Возможны.** **405**, **500** при внутренней ошибке.

---

### `GET /files/{file_id}`

Отдаёт **байты оригинала**. **Без** заголовка `Authorization`: так может ходить **EdgeCache** при промахе кэша или ревалидации.

**Успех: 200.**

- Тело ответа — содержимое файла.
- Заголовки: **`Content-Type`** по сохранённому типу, **`ETag`** в кавычках, **`Cache-Control: public, s-maxage=<N>, max-age=<N>`**, где **N** берётся из **`download_url_expiry`** в `config.yml`.

**Условный GET.** Клиент шлёт **`If-None-Match`** с тем же ETag, что вернул прошлый ответ. Если объект не менялся — **304** без тела, при этом снова выставляются **ETag** и **Cache-Control**.

**Ошибки.**

- **404** — нет такого `file_id`, JSON `{"error":"not found"}`.

**Возможны.** **405**, **500**.

Связь с EdgeCache в общей схеме: при **MISS** кэш запрашивает именно эту ручку у Origin и стримит ответ пользователю; при истечении TTL используется **If-None-Match** и **304**, если файл на Origin тот же.

---

### `GET /health`

Текст **`ok`**, код **200**. Без JSON, для прокоб и балансировщиков.

## Конфигурация

При старте программа один раз читает файл `config.yml`. Путь не задаётся в коде: используется имя файла в **текущей рабочей директории** процесса.

**В Docker** образ собирается так, что рядом с бинарником лежит копия `config.yml` из корня репозитория, а рабочая директория контейнера совпадает с этим каталогом. Любое изменение настроек в репозитории попадает в контейнер только после **пересборки образа**, если вы не подменяете файл томом или bind-mount.

В compose для контейнеров в одной сети в полях вроде `minio_endpoint` и `auth_verify_url` указывают **имена сервисов** из `docker-compose.yml`, например `minio:9000` или `http://stub:8081/auth/verify`. Так контейнер origin обращается к MinIO и к заглушке проверки токена по внутренней сети Docker.

`download_base_url` — адрес, который клиенты используют для запросов к API. Для доступа с вашего компьютера к сервису на порту 8080 это обычно `http://localhost:8080`, даже когда сам сервис в контейнере.

**Без Docker** `config.yml` кладут в ту папку, из которой запускают `go run` или бинарник. Для MinIO и заглушки auth на той же машине в конфиге указывают `localhost` и нужные порты, например `minio_endpoint: localhost:9000` и `auth_verify_url` с хостом `localhost`.

Блок **logging**: уровень логов, формат `json` или `text`, вывод в поток или в файл и путь к файлу при выводе в файл.

Блок **app**: порт HTTP, лимит загрузки в байтах, параметры MinIO, базовый URL для скачиваний, время жизни ссылки в секундах и URL сервиса проверки заголовка `Authorization`.

## Запуск через Docker

Поднимите **только** сервис `origin`.

```bash
docker compose up -d origin
```

Сервис: `http://localhost:8080`. Консоль MinIO: `http://localhost:9001` (логин/пароль по умолчанию в compose: `minioadmin` / `minioadmin`).

Настройки приложения — `config.yml` в образе (копируется при сборке). Для другого окружения отредактируйте файл и пересоберите образ или смонтируйте свой конфиг.

---

## Запуск локально (без Docker)

1. Запустите MinIO (например, в Docker только `minio` из этого compose) или свой инстанс.
2. В `config.yml` укажите `minio_endpoint` с хоста машины (например `localhost:9000`), ключи, бакет, и **реальный** `auth_verify_url` вашего сервиса авторизации.
3. Из корня репозитория:

```bash
cd src && go mod download
cd ..
go run ./src
```

Рабочая директория должна быть корнем `origin-service`, чтобы находился `config.yml`.

## Тесты

Тесты рассчитаны на запуск в Docker (в образе каталог `tests` лежит рядом с кодом модуля).

Для **Юнит-тестирования**  необходимо поднять окружение *test-unit*:

```bash
docker compose up test-unit --build
```

Для **Интеграционного тестирования**  необходимо поднять окружение *test-integration*:

```bash
docker compose up test-integration --build
```
