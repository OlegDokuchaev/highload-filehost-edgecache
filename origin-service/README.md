# Origin service

HTTP-сервис для загрузки файлов пользователей и выдачи ссылок на скачивание. Файлы хранятся в **MinIO** (S3-совместимое хранилище). Доступ к API проверяется через внешний **auth verify** URL: сервис передаёт заголовок `Authorization` и получает идентификатор пользователя.

**Эндпоинты:**

- `POST /files` — загрузка (`multipart/form-data`, поле `file`), нужен `Authorization`
- `GET /users/me/files` — список файлов текущего пользователя
- `GET /files/{id}` — скачивание по идентификатору
- `GET /health` — проверка живости (`ok`)
- `GET /docs/` — Swagger UI

Параметры сервиса задаются в файле `config.yml`. Описание полей см. ниже.

---

## Конфигурация

При старте программа один раз читает файл `config.yml`. Путь не задаётся в коде: используется имя файла в **текущей рабочей директории** процесса.

**В Docker** образ собирается так, что рядом с бинарником лежит копия `config.yml` из корня репозитория, а рабочая директория контейнера совпадает с этим каталогом. Любое изменение настроек в репозитории попадает в контейнер только после **пересборки образа**, если вы не подменяете файл томом или bind-mount.

В compose для контейнеров в одной сети в полях вроде `minio_endpoint` и `auth_verify_url` указывают **имена сервисов** из `docker-compose.yml`, например `minio:9000` или `http://stub:8081/auth/verify`. Так контейнер origin обращается к MinIO и к заглушке проверки токена по внутренней сети Docker.

`download_base_url` — адрес, который клиенты используют для запросов к API. Для доступа с вашего компьютера к сервису на порту 8080 это обычно `http://localhost:8080`, даже когда сам сервис в контейнере.

**Без Docker** `config.yml` кладут в ту папку, из которой запускают `go run` или бинарник. Для MinIO и заглушки auth на той же машине в конфиге указывают `localhost` и нужные порты, например `minio_endpoint: localhost:9000` и `auth_verify_url` с хостом `localhost`.

Блок **logging**: уровень логов, формат `json` или `text`, вывод в поток или в файл и путь к файлу при выводе в файл.

Блок **app**: порт HTTP, лимит загрузки в байтах, параметры MinIO, базовый URL для скачиваний, время жизни ссылки в секундах и URL сервиса проверки заголовка `Authorization`.

## Запуск через Docker

Поднимите **только** сервис `origin`.

```bash
docker compose up -d origin
```

Сервис: `http://localhost:8080`. Консоль MinIO: `http://localhost:9001` (логин/пароль по умолчанию в compose: `minioadmin` / `minioadmin`).

Настройки приложения — `config.yml` в образе (копируется при сборке). Для другого окружения отредактируйте файл и пересоберите образ или смонтируйте свой конфиг.

---

## Запуск локально (без Docker)

1. Запустите MinIO (например, в Docker только `minio` из этого compose) или свой инстанс.
2. В `config.yml` укажите `minio_endpoint` с хоста машины (например `localhost:9000`), ключи, бакет, и **реальный** `auth_verify_url` вашего сервиса авторизации.
3. Из корня репозитория:

```bash
cd src && go mod download
cd ..
go run ./src
```

Рабочая директория должна быть корнем `origin-service`, чтобы находился `config.yml`.

## Тесты

Тесты рассчитаны на запуск в Docker (в образе каталог `tests` лежит рядом с кодом модуля).

Для **Юнит-тестирования**  необходимо поднять окружение *test-unit*:

```bash
docker compose up test-unit --build
```

Для **Интеграционного тестирования**  необходимо поднять окружение *test-integration*:

```bash
docker compose up test-integration --build
```
